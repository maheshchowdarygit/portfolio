## Overview

A capstone systems engineering project showcasing low-level algorithmic design, concurrent systems programming in Go, and information retrieval fundamentals without relying on external search engines like Elasticsearch or Lucene.

---

## Problem

Modern web applications frequently require full-text search over internal documentation, code repositories, or local knowledge bases. Off-the-shelf enterprise solutions (like Elasticsearch, Solr, or Algolia) introduce hefty JVM overhead, complex cluster operational requirements, and high idle memory consumption.

For resource-constrained internal environments and desktop/embedded utilities, there is a clear demand for a single-binary, lightning-fast search engine with:
- Sub-20ms tail query latencies across 100,000+ technical documents.
- Minimal runtime memory overhead (< 100MB RAM).
- Zero external dependencies or managed infrastructure.

## Approach

To achieve maximum throughput and deterministic latency, the engine was built from the ground up around standard Information Retrieval (IR) pipelines:

1. **Text Pipeline & Normalization**:
   - Implemented a zero-allocation streaming text tokenizer.
   - Built a custom Porter Stemming algorithm and English stop-word filter to compress vocabulary while preserving semantic stems.
2. **Inverted Index Data Structure**:
   - Engineered an in-memory inverted index mapping term IDs to sorted posting lists containing document IDs and term frequencies.
   - Employed delta encoding (variable-byte integer compression) to drastically reduce memory footprint of dense posting lists.
3. **BM25 Probabilistic Ranking**:
   - Implemented Okapi BM25 scoring with tunable hyperparameters ($k_1 = 1.2$, $b = 0.75$) to account for term frequency saturation and document length normalization.
4. **Concurrent Ingestion & Query Execution**:
   - Designed a worker-pool crawler and indexer utilizing Go goroutines and buffered channels.
   - Implemented thread-safe read-write locking (`sync.RWMutex`) to enable concurrent read queries while background indexing is active.

## Architecture & Tech Stack

```
[ Ingestion Pipeline ]
  Files / Webpages ─► Worker Pool (Goroutines) ─► Tokenizer & Stemmer ─► Posting List Accumulator
                                                                                   │
                                                                                   ▼
[ Storage & Retrieval ]                                                    Inverted Index
  HTTP GET /search?q=query ──► Query Parser ──► Postings Intersection ──► BM25 Ranking Engine ──► JSON Response
```

### Core Technologies
- **Language**: Go (Golang 1.22) — leveraging strict static typing, garbage collector predictability, and lightweight goroutines.
- **Ranking**: Okapi BM25 with document length normalization.
- **Compression**: Variable-byte integer encoding on postings delta-lists.
- **Transport**: Standard library `net/http` with zero-allocation JSON serialization.
- **Testing**: Automated fuzz testing and micro-benchmarking using Go's `testing.B`.
