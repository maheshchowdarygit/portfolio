## Overview

A systems programming project built from the ground up in Go, implementing a full-text search engine without external dependencies like Elasticsearch or Lucene. It processes 1,600+ documents through an end-to-end TF-IDF pipeline and packages into a self-contained binary under 20MB.

---

## Problem

Modern applications often require fast, local text search across internal documents, technical documentation, or local notes. External enterprise search engines introduce heavy runtime runtimes (JVM), complex cluster configurations, and significant memory overhead.

The objective was to engineer a lightweight, standalone search tool with:
- Sub-10ms query response time across real document collections.
- Minimal operational complexity: single executable binary without external daemons.
- Efficient memory usage through custom inverted-index algorithms.

---

## Approach

The search engine implements a complete four-stage Information Retrieval (IR) pipeline:

1. **Document Collection & Ingestion**:
   - Reads unstructured text documents and technical files from local storage.
   - Cleans and normalizes tokens (case normalization, punctuation stripping, and stop-word filtering).
2. **Text Parsing & Tokenization**:
   - Streaming tokenizer designed for low garbage-collection pressure.
   - Custom stemming to map inflected words to common stems.
3. **Inverted Index & TF-IDF Ranking**:
   - Inverted index data structure mapping unique vocabulary terms to sorted document posting lists with term frequencies.
   - TF-IDF (Term Frequency - Inverse Document Frequency) scoring algorithm to rank relevant documents based on specificity and frequency.
4. **Metadata Storage with SQLite**:
   - Embedded SQLite database alongside the inverted index to store structured metadata (file paths, timestamps, document digests, and snippet previews).
   - Achieved sub-10ms query latency at scale by optimizing memory layouts and postings list intersections.

## Architecture & Tech Stack

```
[ Documents ] ──► Parser & Tokenizer ──► Inverted Index Builder ──► In-Memory Postings
                                                    │
                                                    ├──► SQLite (Document Metadata & Hashes)
                                                    ▼
[ User Query ] ──► Tokenizer ──► Postings Intersection ──► TF-IDF Scorer ──► Top Results (<10ms)
```

### Core Technologies
- **Language**: Go (Golang) — strict typing, high concurrent performance, predictable memory layout.
- **Algorithm**: TF-IDF ranking pipeline (collection → parsing → indexing → query).
- **Storage**: Custom in-memory inverted index + embedded SQLite for structured metadata.
- **Packaging**: Single cross-platform deployable binary under 20MB.
